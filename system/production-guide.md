# Production Guide

## 1. 完成条件

ThinkMoveの資料は、見た目を整えるだけでは完成しない。

> 読み手が状況を理解し、何を判断し、次に誰が何をするか分かる。

制作前に次を固定する。

- Audience：誰が読むか
- Job：資料が果たす仕事
- Decision：何を決めてほしいか
- Takeaway：中心結論
- Evidence：結論に必要な根拠
- Format：口頭説明か単独閲覧か

## 2. sourceを固定する

sourceの文章、表、画像、画面、発言を列挙する。確認できない内容は生成しない。

資料本文を作る場合、豊藏固有の一次情報を2つ以上使う。一次情報が足りなければ、先に素材不足を報告する。

## 3. タイトル列を先に作る

画像生成前に、全ページのタイトルだけを並べる。

- タイトルはテーマ名ではなく、そのページの結論
- タイトルだけで論理が追える
- 同じ結論の言い換えを続けない
- 最終ページは判断事項または最初の一歩で閉じる

## 4. ページ設計

各ページについて次を1行ずつ定義する。

- Claim：読後に残す主張
- Evidence：見せる根拠
- Visual job：画像が担う理解
- Must render：必ず見える文字・数字
- References：渡す参照画像
- Avoid：誤生成しやすい要素

## 5. visual familyを固定する

最初に表紙または基準ページを生成し、承認した画像を後続ページのstyle referenceとして使う。

- 比率は16:9
- 全ページでpalette、線、陰影、人物比率、情報密度を揃える
- 同じ構図を3ページ以上続けない
- 同じ画像を別ページで使い回さない
- 用途に合うtasteを1つだけ主基準にする

## 6. GPT-image2で完成画像を生成する

1ページごとに`prompts/base-slide.md`を埋める。

- 画面全体を生成する
- ロゴ、人物、写真、図解も生成画面へ含める
- 後処理用の空白やプレースホルダーを作らない
- 日本語は短く、画面に必要な量だけ描かせる
- 正確さが必要な数字はsourceと同じ表記をpromptへ明示する

## 7. 不合格ページを再生成する

文字修正やロゴ差し替えを後工程で行わない。

不合格理由を1〜3点へ絞り、[`../prompts/regeneration.md`](../prompts/regeneration.md)で再生成する。修正指示を積み重ねすぎて崩れた場合は、元のbase promptへ戻って作り直す。

## 8. デッキとしてQAする

個別ページの美しさだけでなく、contact sheetで次を確認する。

- ページ順で論理がつながる
- 世界観が途中で別ブランドにならない
- 情報量にリズムがある
- 表紙だけが派手すぎない
- 最終ページが次の判断へ接続する

## 9. 格納

合格したPNG/JPEGをそのままPPTXまたはPDFへ格納する。格納工程で文字やロゴを追加しない。
